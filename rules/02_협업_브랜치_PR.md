# 02. 협업 · 브랜치 · PR

팀원 전원이 이 저장소를 연결해 함께 쓴다. 충돌 없이 겹쳐 일하기 위한 규칙.

## 브랜치
- **브랜치 하나 = 목적 하나.**
- 슬랙 호출 세션은 `claude/slack-session-*` 브랜치가 **자동 생성**된다. 그 브랜치에서만 작업하고, 다른 브랜치에 임의로 push하지 않는다.
- 사람이 직접 작업할 때 네이밍(폴더식, BIDDING `rules/05`와 동일 사상):
  - `work/<사람토큰>-<내용>` — 일반 작업
  - `rules/<사람토큰>-<내용>` — 규칙·문서(CLAUDE.md·rules·README)
  - `fix/<사람토큰>-<내용>` — 수정
  - `try/<사람토큰>-<내용>` — 실험
- `<사람토큰>`은 본인 이름 로마자. **토큰 표의 정본은 BIDDING `rules/05`**를 따른다(공개 저장소라 여기 열거하지 않음).

## main 보호
- **main에는 강석우·김재민만 push.** 그 외 모든 사람·AI는 브랜치 + PR.
- **`git push --force` 금지(어떤 경우에도).** 남의 브랜치 history 재작성·강제 덮어쓰기 금지.
- 빈 커밋으로 CI 흔들기, PR 닫았다 열기 금지.

## PR
- PR 생성은 **요청자가 명시적으로 요청할 때만.**
- PR 설명에는 호출된 **슬랙 스레드 링크**를 남긴다.
- 리뷰 코멘트/CI는 올린 사람이 끝까지 책임지고 끌고 간다. 테스트를 끄거나 우회해 초록불 만들지 않는다.
- 다른 세션 변경을 섞지 말고 **이번 작업 경로만** 스테이징·커밋한다.

## 커밋 메시지
- 형식: `[영역] 무엇을` (한국어). 예: `[rules] 클사원 협업 규칙 추가`.
