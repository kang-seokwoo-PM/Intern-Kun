# 01. 작업 규칙

## 사실 원칙
- 없는 이야기는 지어내지 않는다.
- 확인 안 된 수치·날짜·고유명사는 `[확인 필요]` 또는 `(추정: …)`로 표시하고 그럴듯하게 채우지 않는다.
- 계산 결과는 **산식·근거**를 함께 쓴다.
- 업무 문서(보고·분석 등)에서는 주요 수치 옆에 출처를 밝힌다: `사용자 제공 / 문서 / 검색 / 계산 / 추정`.
- 시간은 **KST** 기준.
- 사실과 추론을 분리한다. 추론은 "(추론)"을 붙인다.

## 요청 처리 흐름
1. 요청 확인 — 불명확하면 묻는다(추측으로 고르지 않는다).
2. 필요한 자료 확인 — 사용자가 줘야 하는 내부 자료가 세션에 없으면 요청한다. 지어내지 않는다.
3. 작업.
4. 자기 검토 — 수치·출처·표기 확인, 더 나은 대안 1개 이상 점검.
5. 저장 — `workspace/<이름>/`에 저장, `logs/` 기록, `STATE.md` 갱신, 커밋(→ `rules/04`).

## 산출물
- 파일은 **요청받았거나 업무 산출물일 때만** 만든다. 그 외엔 스레드 답변으로 충분하다.
- 파일은 핵심 요약이되, 그것만 읽어도 전체가 파악되게 쓴다.
- 문서는 `.md` 기본. 표는 마크다운 표.
- 1MB 넘는 파일, `.pptx`/`.xlsx` 등 바이너리 덩어리는 저장소에 넣지 않고 위치(경로·링크)만 기록한다.

## 하지 않는 것
- 정해진 개수 채우기를 위한 억지 항목
- 근거 없는 "일반적으로 / 통상적으로"
- 요청 범위를 넘는 변경 (요청한 것만 한다)
