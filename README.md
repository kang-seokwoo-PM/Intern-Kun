# 인턴쿤 (Intern-Kun)

팀 공용 AI 사원 **클사원**의 작업 환경 저장소. 팀원 각자가 이 저장소를 연결해 두고 **Slack에서 호출**해 일을 맡긴다.

## 한눈에 보는 구조

```
Intern-Kun/
├─ README.md            사람용 진입점 (지금 이 문서)
├─ CLAUDE.md            AI가 가장 먼저 읽는 지침 (페르소나 + 절대 규칙)
├─ AGENTS.md            Codex/GPT 진입점
├─ 팀원_시작하기.md       팀원 온보딩 (연결·호출·주의사항)
├─ STATE.md             지금 상태 · 다음 할 일 (세션 간 기억)
├─ CHANGELOG.md         규칙·구조가 왜 바뀌었나
├─ rules/
│  ├─ 00_페르소나_슬랙.md    클사원의 말투와 슬랙 행동 기준
│  ├─ 01_작업규칙.md        사실 원칙 · 검토 방식 · 산출물
│  ├─ 02_폴더링_브랜치.md    폴더 · 파일명 · 브랜치 · 충돌 방지
│  ├─ 03_보안_반입금지.md    저장소에 넣으면 안 되는 것
│  └─ 04_기록_연속성.md     로그 · STATE 갱신 방법
├─ workspace/           사람별 작업 폴더 (workspace/<이름>/)
├─ logs/                날짜별 작업 기록 (_템플릿.md)
└─ .github/pull_request_template.md
```

## BIDDING 레포에서 가져온 것 / 인턴쿤에 맞게 바꾼 것

| BIDDING의 장치 | 인턴쿤 반영 |
|---|---|
| CLAUDE.md = AI가 먼저 읽는 지침 | 그대로 채택 (`CLAUDE.md`) |
| AGENTS.md = Codex 진입점 | 그대로 채택 |
| rules/ 번호 체계 | 5개로 축소 (페르소나·작업·폴더링·보안·기록) |
| STATE.md + logs/ = 세션 연속성 | **더 중요해짐**: 호출마다 새 세션이라 이 저장소가 유일한 기억 |
| vN 불변 · 1인 1파일 · 단독 소유 STATE | 충돌 방지 3장치 그대로 채택 |
| 폴더식 브랜치(`bid/ tool/ rules/ try/`) | `work/<사람>-<작업>` · `rules/<사람>-<작업>` 으로 단순화 |
| main은 소수만 push | 같은 원칙: 이름 브랜치 → PR |
| 비딩 프로젝트 폴더 · 플러그인 · 전용 명령 | **가져오지 않음** (인턴쿤은 범용 사원이라 아직 불필요) |
| 팀원 명부(`rules/06`) | **가져오지 않음** (개인정보라 이 저장소에 복제하지 않음) |

## 한 줄 원칙

지어내지 않는다 · 모르면 `[확인 필요]` · 기억은 저장소에 · main엔 직접 push하지 않는다.
